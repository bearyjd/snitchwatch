# #379: Retire the Tauri shell (and decide the vendored `web/` frontend)

Issue #379. Owner decision 2026-11-17: retire the Tauri shell. Since #35 it runs only with
`SNITCHWATCH_DEV_TCP=1`. Settled decision 4 (`CLAUDE.md`) names Qt6/Kirigami as the long-term
GUI and keeps the Tauri crate only "during the migration". The 2026-07-11 owner gate in
`docs/superpowers/plans/2026-07-04-kirigami-shell-rewrite.md:14` ("keep both
`crates/snitchwatch-tauri/` and `web/` until a packaged release ships") is met: `gh release
list` shows `r16.1` and `r16.2` (Latest, 2026-11-16) published, and
`.github/workflows/candidate-gui.yml:149` expects `/app/bin/snitchwatch-kirigami` as the
shipped GUI binary.

Related: #378 item 1 (Tauri `ws_proxy_bind` not checked to be loopback) was fixed in #380
(`crates/snitchwatch-tauri/src/bridge_runtime.rs:88-96`, `ensure_loopback_proxy_bind`). It
becomes moot once this lands; nothing there needs porting. #35 stays open for #178 (tower).

Branch `docs/379-retire-tauri-plan` (this doc only). Implementation: two PRs, PR 1 then PR 2,
plus an optional PR 3 (follow-ups). Each reviews and reverts alone.

("consumes `RunningBridge` in-process", `:9`) is stale; the code is authoritative.

(`crates/snitchwatch-bridge/src/ws_messages.rs:454-461` macro, variants `:471-610`), Kirigami constructs 31
(`git grep "ClientMessage::<Variant>" crates/snitchwatch-kirigami`). The three it never sends
are `Undo`, `Redo` and `GlobalSettings`. `web/js/app.js:905,922` sends `undo`. The bridge has no
production handler for any of the three: `translator/upstream.rs:83,95-96` groups them with
the messages intercepted elsewhere, and a grep of non-test `snitchwatch-bridge{,-cli}/src`
finds no other match. So they are legacy Little Snitch actions the bridge already ignores,
not a Kirigami gap (UNVERIFIED: the exact value that match arm returns).

**Parity blockers: none found.** Accepted gaps: the uPlot chart's interactivity, and the
non-Linux autostart plugin.

### 2. What depends on the vendored web frontend

The static surface:
- `crates/snitchwatch-bridge/src/web_assets.rs:17-19` (`rust-embed` of `../../web/`),
  `:21-33` (`serve_index`, `serve_asset`, `serve_fallback`).
- `crates/snitchwatch-bridge/src/ws_server.rs:15-20` (doc), `:25-26`, `:132-145` (routes `/`,
  `/assets/*path`, SPA fallback, all under `#[cfg(feature = "web-ui")]`).
- Feature `web-ui` (default): `crates/snitchwatch-bridge/Cargo.toml:18,43-51`;
  pass-through in `crates/snitchwatch-bridge-cli/Cargo.toml:16-20`. `crates/snitchwatch-bridge/src/lib.rs:42-43`.

**Nothing reachable consumes it without Tauri.** Verified:
- The bridge serves HTTP/WS only on its Unix socket (`ws_server.rs:119-130`). No code path
  binds the WS server on TCP: the only non-test `TcpListener::bind` outside Tauri is the dev
  gRPC listener (`crates/snitchwatch-bridge-cli/src/lib.rs:157`).
- `SNITCHWATCH_WS_BIND` is read by no Rust code. It appears only in the four Playwright
  specs (`tests/web_smoke/tests/loads_index.spec.ts:12`,
  `round_trips_ask_rule.spec.ts:13`, `tests/tauri_smoke/tests/{tray_states,wizard_branches}.spec.ts:10`).
  `config.rs:71` reads `SNITCHWATCH_WS_SOCKET` instead.
- So `http://127.0.0.1:3031` exists only while Tauri's loopback proxy runs
  (`crates/snitchwatch-tauri/src/loopback_proxy.rs:1-35`). A browser cannot dial a Unix
  socket.
- `web/js/app.js:55-69` dials `ws://<host>/stream` and needs `window.__SNITCHWATCH_TOKEN__`,
  which only Tauri's `initialization_script` sets (`main.rs:101-119`). Without it the bridge
  rejects `/stream`.
- No Playwright job runs in CI (`grep smoke|playwright .github/workflows/*.yml`: no hits).
- `tests/tauri_smoke` never launches Tauri. It starts `snitchwatch-bridge-cli` and points a
  browser at `:3031` (`tray_states.spec.ts:7-16`; `playwright.config.ts:10`).

Conclusion: `web_smoke` and `tauri_smoke` already cannot pass against `main` without a
running Tauri shell. They also start a bridge **without an isolated `XDG_RUNTIME_DIR`**
(`loads_index.spec.ts:8-15`), which is the #34 socket/token-replacement hazard `CLAUDE.md`
forbids. Keeping `web/` as a dev UI would mean keeping (or rewriting) a token-injecting TCP
proxy. That is the security surface this issue removes.

Other `web/` dependents that must be handled, not just deleted:
- **Shipped icon.** `packaging/flatpak/org.snitchwatch.Snitchwatch.system.yml:134` installs
  `web/icons/snitchwatch.svg` into the shipped Flatpak. The icon is project-owned:
  `web/VENDORED.md:48-50` says upstream has no `icons/` directory. Move it (proposed:
  `packaging/icons/snitchwatch.svg`, plus the two PNGs if anything wants them) before
  deleting `web/`.
- **Legacy-dispatcher test.** `crates/snitchwatch-bridge/src/ws_messages/tests.rs:92-110`
  (`legacy_web_dispatcher_ignores_shell_only_wire_extensions`) does
  `include_str!("../../../../web/js/app.js")`. It is deleted with `web/`. Its purpose
  disappears with the last legacy client.
- **Legacy wire shape.** `ws_messages.rs:494-499` (`remember: bool` accepted when `duration`
  is absent) and `ws_messages/tests.rs:270-276` (`client_set_verdict_parses_legacy_remember_shape`)
  exist for `web/`. **Keep them** in this issue: wire compat is cheap, and removing it is a
  protocol change with its own review. `verdict_wire.rs:61` doc mentions Tauri/web; reword only.
- **Release build.** `packaging/release/build-bridge.sh:36-39` lists `web` in `BUILD_INPUTS`
  (dirty-tree check). `bridge_artifact.py:76-81` (`RELEASE_PACKAGE_ARGS` with
  `--no-default-features`, `WEB_UI_MARKER`), `:1188-1195` (`check_no_web_ui`), and
  `crates/snitchwatch-bridge/tests/release_artifact/pack_layout.rs:326-335` guard the
  release binary against embedding the GPL-2.0-only UI. `justfile:149-153` lints and tests the

- **License text.** `README.md:509-510` (web/ is GPL-2.0-only, `web/VENDORED.md`);
  `docs/packaging/bridge-release-artifact.md:67`; `crates/snitchwatch-bridge/Cargo.toml:45-50`.
- `justfile:51-54` (`web-rebrand`), `:57-62` (`web-smoke*`), `:11-12` (`doctor`).

`tests/bridge_protocol_test.rs` and its modules use only `/stream` over the Unix socket

## Security considerations

- **Removed surface**: the loopback TCP proxy on `127.0.0.1:3031` that forwarded to the
  token-gated WS socket (`loopback_proxy.rs:19-28`) and the in-process token injection
  (`main.rs:60-69,101-119`). After PR 1, no Snitchwatch process listens on TCP except the
  dev-flagged gRPC listener and the spike.
- **No guard is lost.** The guards live in the bridge (`/stream` token handshake, 0700/0600
  socket and token, `OwnerUnixIncoming`, the `DEV_TCP` resolver). Tauri only added
  `ensure_loopback_proxy_bind` (#380), which protects code that is being deleted.
- **PR 2 removes unauthenticated routes.** `/`, `/assets/*` and the SPA fallback were
  unauthenticated static routes (`ws_server.rs:15-20`); after PR 2 the socket serves only
  `/stream`. This shrinks the pre-auth attack surface; the guard test makes it permanent.
- The release binary was already built without `web-ui`; the marker check stays.
- Dev workflows that relied on Tauri now use Kirigami against a bridge-cli (or system bridge).
  No new dev-only listener is introduced.
- Reviewer pass: opus `security-reviewer` on PR 2 (HTTP router change), sonnet `code-reviewer`
  on PR 1.

## Risks and rollback

- **CI apt trimming breaks a build** that implicitly used gtk (e.g. a `-sys` crate via
  `notify-rust` in a default member). Mitigation: the `cargo tree` check before trimming;
  rollback is re-adding packages.
- **Lockfile churn**: the MANIFEST hash changes; the next release candidate is not comparable
  by MANIFEST to `r16.2`. That is expected; release notes say why.
- **Flatpak icon path**: missing it breaks the shipped GUI build. Mitigated by the shape test
  and by moving the icon in its own first commit.
- **Kirigami job still best-effort**: run its tests locally per `CLAUDE.md`.
- **Lost dev convenience**: a browser-based UI for poking the bridge. It did not work without
  Tauri anyway (section 2).
- **Rollback**: each PR is a pure deletion plus doc edits; `git revert` of the merge restores
  it. PR 2 depends on PR 1 only for doc wording, so it can be reverted alone; reverting PR 1
  after PR 2 would restore a Tauri shell with no `web/` to load, so revert in reverse order.
