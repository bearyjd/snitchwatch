## #116 hardening

- **CHANGE_CONFIG guard (done).** `every_other_action_value_is_refused_exhaustively`
  (`daemon_commands/tests.rs`) sends every `type` value from -16 to 256, plus
  `i32::MIN` and `i32::MAX`, and requires that only `CHANGE_RULE` and `DELETE_RULE`
  are queued. Written first.
- **File creation (done).** New `private_files.rs` in the Kirigami crate:
  `ensure_private_dir` (create 0700, then require a real directory of ours and
  tighten an existing one to 0700) and `open_private_append` (no symlink, no FIFO,
  our file, one link, 0600). Used by `panic_hook` (`crash.log`) and `logging`
  (`gui.log`, the dir). With `HOME` unset, state goes under `/tmp/snitchwatch-<uid>`
  instead of `/tmp/.local/...`; that root is checked like the directory itself.
- **panic hook (done, extra).** `main.rs` never installed `panic_hook`, so
  `crash.log`, which the Diagnostics page reads, was never written. It is now
  installed after `logging::init()`.
- **Stale comments (done).** `logging.rs` tungstenite version; `storage.rs` example
  path (`~/.local/state`). The `ANALYZE` / `PRAGMA optimize` note is on
  `require_known_schema`.
- **Stuck-close test (done).** Its 1 s bound now starts when the server has the close
  in hand and sits just under `CLOSE_WAIT`; the fake server counts closes without
  taking the interface lock a stuck close holds.
- **Resident notice outlives the GUI (done, L3).** Shown notices are listed until
  closed; `close_all_open` runs after `app.exec()` in `main.rs`.
- **Secondary cooldown (done, L5).** `CooldownGate::should_fire_for_flow`, keyed on
  (session, program path or name, host) taken from the pending row, beside the
  per-row key. A held-back notice takes neither.
- **QML probes fail when they can't write (done).** The one probe that writes
  (`level_rule_unavailable_once_qml.rs`) now reads the file back and fails if the
  write didn't land. No other probe writes.
- **Hash-shorten long names (done for profiles; blocklists already safe).** Blocklist
  ids are capped at 81 bytes and hashed by `IdComponent` (names are at most 103
  bytes), now pinned by a test. Profile ids were unbounded and sanitized lossily
  (`a/b` and `a_b` shared a name); a non-plain or over-64-byte profile id is now
  cut to 40 characters and hashed.
- **Not mine.** Simulator LOWs, the CreateProfile refusal, profile doc nits: group B.
