# r16 group A: private settings writes (#176) and simulator leftovers (#116)

## #176
1. Symlinked config dir. `ensure_private_dir` (shared by settings, gui.log,
   crash.log, panic hook) follows a symlink in place of the directory once,
   canonicalises it, and holds the real directory to the same checks (ours,
   tightened to 0700). Under the no-HOME root nothing is followed, and
   `ensure_private_root` stays strict. A symlinked `settings.json` stays refused,
   with "<name> is a symlink; Snitchwatch writes only regular files it owns".
   The old "symlinked dir is refused" test is replaced: it now asserts the
   resolve-and-tighten behaviour, plus refusal of a foreign or file or dangling target.
2. GeoIP: `discover_and_open` uses `paths::home_base_rechecked`, which re-runs
   `ensure_private_root` for the no-HOME root instead of the cached result.
   Tested at the pure helper (`home_base_rechecked_from`); the one-line wiring
   in `discover_and_open` reads the process env so it is not unit-tested.
3. Atomic writes: `write_private` writes a `.name.tmp-pid-n` file (create_new,
   O_NOFOLLOW, 0600), fsyncs, renames over the target; a drop guard removes
   the temp on error or panic. Final-path checks (symlink, regular, ours,
   one link) run before anything is written. Tests: failure and panic before
   the rename keep old content and leave no temp; planted temp symlinks are not
   followed. Mutants run in a private copy.
