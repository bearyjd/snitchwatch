## Goal

A read-only way to get history out, which can never write, never hold the writer or a verdict up, never return more than a bounded page, and never show a hole as an empty interval. Concretely: a validated read-only opener, keyset paging over `(ts_ms, id)`, a response that is a **timeline** (events plus the gaps, sessions and standing labels that explain every instant of the window), the bridge-wide admission gate with response slots, cancellation, generation tagging, the 2 s deadline returning a partial page with a usable cursor, and a reader registry the PR 10 control gate can quiesce.

## What exists (explore pass, 2026-11-24)

- `lifecycle.rs:81-122`: `ReaderGate` (non-blocking `try_acquire` -> `ReaderPermit`/`Busy`, `in_use`). Counter only: **no cancellation, no wait-for-idle, no close**. PR 10 needs all three, so PR 9 extends it (see Design 7). `Generation` (`:28`) is the G1 counter; `AcceptanceSeq` is for previews, not used by the reader.
- `sqlite_file.rs:72-100`: `open_owner_only` always `READ_WRITE | CREATE`, `set_permissions(0600)`, then `DEFENSIVE`, `trusted_schema=OFF`, `cell_size_check=ON`; `refuse_unsafe_sidecars` and `file_problem` (`:101`) are reusable. `require_known_schema(conn, schema)` (`:193`) compares `sqlite_master` with an in-memory reference. No read-only variant exists.
- `schema.rs:95-135`: `events` (`id INTEGER PRIMARY KEY`, **no AUTOINCREMENT**, so the newest rowid can be reused after its row is deleted), index `events_ts (ts_ms)` (rowid implicit, so `(ts_ms, id)` is index-ordered); `gaps(start_ms, end_ms, start_exact, cause, count >= 1)` with 10 causes (`GAP_CAUSES`); `sessions(start_ms, end_ms, end_kind)`; `meta.watermark_ms`. v3 adds `prompt_outcome`, `events_prompt_decided`, views `history_candidates`, `history_events` (`correlation.rs:14-40`, adds `possible_duplicate`). v4 adds `meta.expiry_debt_milli`. `schema_sql()` is the reference the reader must pass `require_known_schema` with.
- `ledger.rs:72-90`: `Gap { start_ms, end_ms, start_exact, cause, count }`, doc says count is "at least"; `is_uncertain()`. `read_gaps` (`:379`) reads **all** rows (L1 bounds them: 2% reserve and a row ceiling), `session::read_sessions` (`session.rs:87`) likewise. Neither is windowed.
- `gaps.rs:36-48`: `StandingLabels { nolog, stock_default_unobservable, no_gui_prompts }`, in-memory, session-scoped, produced by `Capture::standing_labels()` (`capture.rs:572`). Never persisted (learning `2026-11-24-history-gap-rows-must-cover-every-snitchwatch.md`).
- Journal mode is **DELETE** (`schema.rs:259`, `writer.rs:434`), not WAL. A reader's SHARED lock therefore blocks the writer's commit (it needs EXCLUSIVE), and the writer waits at most `WRITER_BUSY_TIMEOUT = 250 ms` (`capture_writer.rs:22`), then counts a failure and loses the batch to a `write-failed` gap. A reader that holds a lock for its whole 2 s budget would cost history. This shapes the whole design.
- A read-only connection cannot roll back a hot journal left by a crashed writer; SQLite answers busy/readonly. The reader must report "unavailable, retry", never an empty page.
- Retention (`retention.rs`, PR 8) deletes oldest rows in chunks and writes `evicted` gap rows in the same transaction; process-share eviction writes a marker over the span of that process's removed rows, **inside which other processes' rows survive**. #430: a prefix marker and a process marker can be indistinguishable at ts 0 and merge, extending a span over surviving events.
- `bridge-cli/src/analysis_export.rs`: the pattern for the permit-owned-by-the-worker rule (`WORK_LIMIT = 2`, 10 s deadline). History uses 2 s, not 10 s.
- #419 (`gaps.rs` ~253): after an outage the first ping's upstream loss of `n` is written as two rows (last ping to down edge, daemon-up to ping) with `count >= 1` each. For `n = 1` the sum is 2; for `n >= 2` the sum is `n` but the pre-outage row asserts at least one loss that may not have happened. The counter proves only a lower bound over the whole interval.

## Design

New `history/reader.rs` (policy, query, limits; under 400 lines), `history/timeline.rs` (pure coverage computation, no SQL, so it can be property-tested), `history/reader_registry.rs` (admission, cancel, quiesce). `sqlite_file.rs` gains `open_owner_only_readonly` (it is 400+ lines already; the function is small and shares `file_problem`).

1. **Read-only opener, no write path.** `open_owner_only_readonly(path)`: same `refuse_unsafe_sidecars`, same `O_NOFOLLOW` open of the file but `read(true)` only, `create(false)`, and the same `file_problem` checks (regular, ours, link count); **no `set_permissions`**; then `SQLITE_OPEN_READ_ONLY | NO_MUTEX | NOFOLLOW` (no CREATE), `DEFENSIVE`, `trusted_schema=OFF`, `cell_size_check=ON`, `PRAGMA query_only = ON`. A missing file is `Unavailable("no history")`, never created. The reader never calls `Engine`, `Store`, `transact`, or any `execute`; `reader.rs` imports no write type. Structural proof: a test that opens the reader and attempts `INSERT`, `DELETE`, `CREATE TABLE`, `PRAGMA journal_mode = WAL` and `PRAGMA wal_checkpoint`, each refused, and a byte-identical file (sha256 plus mtime plus mode) after a full reader session.
2. **A fresh connection per query**, opened on the blocking worker and closed before the permit is returned. Cost is about a millisecond at 2 queries at once, and it guarantees no reader fd survives a clear's unlink (C1).
3. **Limits (all enforced in the reader, none left to the transport).**
   - Rows: at most 200 events per page (D8), and at most `GAP_ROWS_PER_PAGE = 100` gap rows and 100 session rows.
   - Bytes: 256 KiB per response (D8). The reader sizes a page with `row_bytes(row)` = sum of text/blob field lengths plus a fixed 160 B per event and 64 B per gap/session (an upper bound of the PR 11 JSON, which PR 11 re-verifies against the real serializer). The page is cut at the first row that would cross 252 KiB (4 KiB for the header, labels and cursor).
   - Time: 2 s per query (D8), enforced as **many short statements**, not one long one: the read is chunked into index windows of at most `SCAN_WINDOW = 512` events, each statement with a `progress_handler` that interrupts at `STATEMENT_BUDGET = 100 ms` or on cancel. 100 ms is under the writer's 250 ms busy timeout, and each statement runs in autocommit, so **no read lock is held between statements** and the writer can commit. The deadline and the cancel flag are checked between statements.
   - Scan: a per-query cap of `SCAN_ROWS_MAX = 20,000` index entries examined (filters make "rows returned" a poor bound). On any limit the reader returns what it has plus a cursor and a `partial` reason (`rows`, `bytes`, `time`, `scan`, `cancelled`). A partial page with zero rows is legal and still carries an advanced cursor (`scanned_to`), so a sparse filter always makes progress.
   - Window: never "return everything": a request with no cursor starts at the head; a `limit` above 200 is clamped, not an error.
4. **Order and cursor.** Newest first by `(ts_ms DESC, id DESC)` (what the GUI shows; Open decision 1). The cursor is `{generation, direction, ts_ms, id, scanned_to}`, opaque to callers, keyset only, never `OFFSET`. The seek is `ts_ms < ?1 OR (ts_ms = ?1 AND id < ?2)` and the plan must use `events_ts` with no temp B-tree and no table scan (EXPLAIN QUERY PLAN test; this is also #429 item 3's tie problem).
   - **Concurrent inserts:** a row inserted ahead of the cursor (newer than it) is simply not in later pages; the client re-reads the head to see it. A late row inserted behind the cursor (older `ts_ms`, as pings can be) appears exactly once on a later page. No row is returned twice, and no row that exists for the whole paging is skipped. Rowid reuse is harmless because the key carries `ts_ms`.
   - **Eviction:** the cursor is a value, not a row reference, so a cursor whose row was evicted still works and resumes at the next surviving older key. Paging into the evicted region ends at the retention floor with the `evicted` marker covering it (Design 5), and says `end = retention_floor`, not `end = oldest`.
   - **Clear / disable / retention change:** the cursor carries the generation; a cursor from an older generation is refused `stale-generation` and the client restarts. A page that finishes after the generation moved is dropped (G1) and never delivered. Eviction does **not** bump the generation (it is not a control operation).
   - **Ordering caveat:** inside a `clock-jump` gap, `ts_ms` order is unreliable (D6). The page says so through the gap row; the order is still deterministic by `(ts_ms, id)`.
5. **The response is a timeline.** A page is `{generation, events[], coverage[], sessions[], gaps[], standing, retention_floor, partial?, next_cursor?}`. For the page window `[w_lo, w_hi]` (from the last returned key to the cursor boundary, or to the head) the reader loads every gap overlapping the window (indexed range on `start_ms`/`end_ms`; bounded by L1) and every session overlapping it, then `timeline::coverage(window, sessions, gaps, events)` returns segments that **tile the window exactly**: `recorded` (a session was running; may hold events), `gap{cause, start_exact, count_min, counted_exactly: false}`, `not-recording` (no session: only legitimate when a `disabled` or `bridge-down` gap covers it), and `unexplained` (anything left over; should be empty, and its presence is a bug the test suite asserts cannot happen, but the wire still carries it rather than an empty span).
   - **Holes:** the function treats overlap as fine and a hole as the one failure (learning: floors and clamps that shrink a gap leave silent holes). It never clips a gap to the window in a way that shrinks it; it reports the gap's own bounds and a `clipped` flag for display only.
   - **Gap bytes shrink the window, not the gap:** gap and session rows are counted in the 256 KiB. If they do not fit with the events, the window is shortened (fewer events) until they do. If gaps alone exceed their 100-row cap, the page ends early with `partial: gaps` and a cursor at the window edge, so no gap is dropped and none is truncated mid-list.
   - **Uncertain spans** (`cause = uncertain`, `start_exact = false`) are returned as "between X and Y; N restarts/gaps; coverage uncertain" and never as continuity.
   - **Evicted markers (#430):** every `evicted` row is returned as `evicted{span, count_min}` with the explicit meaning "some events in this span were removed by retention", not "nothing here". The reader never claims that a span containing a marker has no surviving events, and never draws a marker over an event it also returns without `overlaps_events: true`. Without a persisted discriminator it cannot tell a prefix marker from a process marker, so it does not try (Open decision 3). Everything older than `retention_floor` (earliest surviving `ts_ms`) that no gap or session explains is shown as `evicted-or-before-recording`, never blank.
   - **End states:** `end = head`, `end = retention_floor`, `end = oldest_recorded` (no sessions earlier), and `unavailable` (history off, no file, hot journal, schema refused, closed by a control operation). "Unavailable" is a distinct state from "empty", on every path (a missing or refused file must never yield `events: []`).
6. **Standing labels.** The reader does not own them; the caller passes the `StandingLabels` snapshot (`Capture::standing_labels()`), and each page carries it in the header together with `scope: "current_session"` and the session start. For any part of the window before the current session the labels are `unknown`, not `false`: they are not persisted, and a stock-daemon default-applied hole exists in every session that ran without a fork marker. When no capture is running (history disabled) the page carries `labels: unavailable` and the coverage says `not-recording`. `nolog` is always stated while history is on. The no-GUI-prompts flag, once set, stays set for the session.
7. **Admission and the registry.** `ReaderRegistry` wraps `ReaderGate` (limit `MAX_READERS = 2`, D8): `try_acquire()` returns a `ReaderTicket { permit, cancel: CancelToken, interrupt: InterruptHandle }` or `Busy` immediately, never queued. The permit is owned by the **blocking worker**, moved in before the worker starts, and dropped only when the worker returns (also on panic), so a cancelled query keeps its slot until it has stopped (the `analysis_export.rs` pattern). Per connection a new query or a disconnect cancels the previous one (cancel token plus `sqlite3_interrupt`; the next progress tick and the between-statement check see it). Two response slots of 256 KiB (a second small semaphore) bound memory: a page is built into a slot, handed to the sender, and the slot is released when the page is sent or after `SEND_DEADLINE = 5 s` with the connection closed (slow-consumer bound; Open decision 5). The reader itself never blocks on a socket.
   - **PR 10 interplay.** The registry adds what the control gate needs and PR 9 tests with a stub caller: `close()` (new readers get `Busy`/`unavailable: control operation in progress`), `cancel_all()`, `wait_idle(deadline)` (all permits returned, workers exited), `reopen()`. PR 10's order is: take the barrier, advance the generation, `close` then `cancel_all` then `wait_idle`, then unlink/rewrite, then `reopen`. A reader mid-query when clear arrives is stopped before unlink and delivers nothing afterwards; if `wait_idle` times out the control operation fails closed (refuses, leaves everything unchanged) rather than unlinking under a reader. A control operation never waits behind a *queued* reader (there is no queue).
   - **Verdict path:** the reader holds no cache or verdict lock, takes no lock shared with the writer thread other than SQLite's own file locks (which Design 3 bounds), and runs on its own blocking pool. A reader that sees `SQLITE_BUSY` (writer in its commit) retries the statement at most twice with 10 ms sleeps, then ends the page `partial: busy` with a cursor: reads yield.
8. **Counts that are lower bounds (#419).** Every gap count is a **minimum**. The page type has `count_min` and `count_is_lower_bound: true` for every cause (a flag, not a convention), the GUI text is "at least N", and no summary field is called "total lost". Range summaries return `lost_at_least`, `gap_rows`, `covered_fraction` and `exclusions` (the standing labels), never one exact number.
   - **The pair problem.** A lower bound must not overcount, and the #419 pair can (n = 1 gives 2). Read-time rule: an `upstream-loss` row whose `end_ms` equals a `daemon-disconnected` row's `start_ms` and the next `upstream-loss` row whose `start_ms` equals that row's `end_ms` form a *bracketing pair*; the pair contributes `max(1, c1 + c2 - 1)` to `lost_at_least` (valid for n = 1 and for n >= 2, since the pair sums to `n` there and `n - 1` never exceeds the truth). Each row is still returned with its own count and `part_of_pair: true`, so the display is "at least 1 on each side" without a summed claim. If the rows were merged away from this shape the rule simply does not fire and the total can only err on the high side by the same one, so the summary carries `may_overcount_by_pairs: n` (the number of daemon-disconnected gaps adjacent to upstream rows). No schema change (Open decision 2).
   - `evicted` counts are lower bounds too (#429 item 4 undercounts coalesced rows); `uncertain` counts restarts, not events, and is labelled so.
9. **Generation and `repeat_count`.** Events carry `repeat_count` (a coalesced connection stands for that many); the reader returns it and `possible_duplicate` (from `history_events`, never from `events` directly, so PR 6's flags are not lost). Strings are returned as stored (already capped by S1); rendering is PR 13's job.
10. **Nothing in this PR changes the writer, schema, or wire.** No schema bump (see Open decisions 2 and 3 for why one might be wanted later).

## Tests first (each seen to fail before the code exists, then pass)

Opener
1. The read-only opener refuses everything the writable opener refuses (symlink, FIFO, non-regular, foreign owner, hard-linked, unsafe `-journal`/`-wal`/`-shm`) and **never creates** a missing file, never changes mode/owner/mtime of the db or any sidecar; a missing file is `Unavailable`, not an empty store.
2. Write attempts fail (`INSERT`, `DELETE`, `CREATE`, `PRAGMA journal_mode=WAL`, `wal_checkpoint`, `VACUUM`, `ATTACH`); the db is byte-identical after a full reader session; a database with a changed schema is refused by `require_known_schema`.
3. A crashed writer's hot journal: the reader reports `unavailable(retry)`, leaves the journal untouched, and never returns `events: []`.

Limits
4. 201 rows -> 200 returned with a cursor; 300 KiB of rows -> a page under 256 KiB with a cursor; the byte bound holds for worst-case rows (every field at its cap) and for gap-heavy windows.
5. Deadline: a slow query (a progress-handler stall or a huge store) ends at 2 s plus one statement budget with `partial: time` and a cursor that resumes with no duplicate and no skip; a sparse filter returns zero rows, `partial`, and an **advanced** cursor.
6. Each statement is at most 100 ms and **no read lock is held between statements**: a writer committing during a maximal read (two readers at their cap) succeeds inside `WRITER_BUSY_TIMEOUT` and loses no batch (no `write-failed` gap, no queue overflow).
7. EXPLAIN QUERY PLAN: the page query and the cursor seek use `events_ts`, no `USE TEMP B-TREE`, no table scan; 50,000 rows tied at `ts_ms = 0` page in bounded VM steps.

Cursor stability
8. Paging while the writer inserts newer rows: no duplicate, no skip of existing rows; a late older row appears once; paging while the writer inserts at the cursor's own `ts_ms` is stable by id.
9. Paging while retention evicts the oldest rows (real `retention` pass between pages): the cursor over an evicted row still resumes, the page ends `end = retention_floor`, and the evicted marker is in the coverage; the newest-row id reuse case does not duplicate.
10. A cursor from before a generation bump is refused `stale-generation`; a page that completes after the bump is dropped, not delivered.

Timeline and holes
11. Property test (`timeline_tests.rs`): over random sessions, gaps (overlapping, adjacent, clock-jump spans, uncertain spans, zero-length) and windows, `coverage` tiles the window exactly (no hole, no inversion), never shrinks a gap, and `unexplained` is empty whenever the ledger is consistent. A deliberately inconsistent ledger yields `unexplained`, never a blank.
12. After a daemon outage and first ping, the page covers last ping to down edge, the outage, and daemon-up to ping with no uncovered instant (uses the PR 7 writer to produce the rows, not hand-built rows).
13. Gap bytes shrink the window: 150 gap rows plus 200 events never exceed 256 KiB, no gap is dropped or truncated, the page ends `partial: gaps` with a cursor.
14. `evicted` markers: a process marker spanning surviving events of another process is returned with `overlaps_events`, never as "empty"; the region below `retention_floor` is `evicted-or-before-recording`, never blank; the #430 ts-0 merge case is returned as the stored rows say, and the test documents the known limit (`#[ignore]` is not used: it asserts today's behaviour and names #430).
15. Standing labels ride on every page with `scope: current_session`; earlier sessions are `unknown`; with no capture running the page says `unavailable`, not `false`.
16. History off / not enabled / no file / schema refused: `unavailable` on every path, never an empty page.

Counts (#419)
17. Every gap count is `count_is_lower_bound`; the n = 1 outage pair yields `lost_at_least = 1` (not 2), n = 5 yields 4 or more, and never above the true loss; a pair broken apart by merges sets `may_overcount_by_pairs`.

Admission and cancel
18. Three concurrent queries: two run, the third gets `Busy` at once (never queued); a cancelled query keeps its permit until its worker has exited (held-permit assertion with a stalled worker); the permit returns on panic.
19. A replacement query and a disconnect each cancel the previous query on that connection; the cancelled one ends within a statement budget.
20. Slow consumer: a sink that never reads holds at most 2 response slots of 256 KiB, then the slot is reclaimed at `SEND_DEADLINE` and further queries still get a slot; memory is bounded.
21. Registry for PR 10 (stub caller): `close` refuses new readers with a distinct reason, `cancel_all` stops an in-flight reader before `wait_idle` returns, `wait_idle` times out when a worker is stuck (and the caller must then fail closed), `reopen` admits again; a reader mid-query when a stub "clear" unlinks the file delivers no row afterwards.
22. Reads never block a verdict: with two maximal readers running, an `AskRule` through `mock_opensnitchd` completes inside its normal time (timed; the real WS re-run is PR 11).

Isolation: every test that starts a bridge uses a tempdir `XDG_RUNTIME_DIR` and `XDG_STATE_HOME`; no live `opensnitchd`. History-off CLI tests need a short `TMPDIR` and `CARGO_TARGET_DIR` in the same shell command.

## Decisions (owner accepted every recommended option on 2026-11-24)

Each item below keeps its option text; the option marked recommended is the decision. Summary: (1) newest-first, time cursor only, no filters; (2) #419 handled at read time (pair the rows, count sum minus 1, never over-report), no schema change; (3) #430: every `evicted` row means "some events removed", never an empty span, no discriminator column; (4) standing labels for earlier sessions are `unknown`, not `false`; (5) a response slot is released when the page is sent or after a 5 s send deadline (to confirm in PR 11); (6) reader limits are constants in `reader.rs`; (7) refusal during a control operation is a distinct "unavailable: control operation in progress"; (8) a fresh read connection per query.

## Decision text (as proposed)

1. **Sort order and filters in v1.** Options: (a) newest-first, time-range cursor only; (b) newest-first plus an optional process-path and verdict filter; (c) both directions. Recommendation: (a) plus a forward `direction` on the cursor type only if PR 13 asks for it. Why: D8 and PR 13 specify only paged history; filters multiply the scan bound and the plan tests, and the cursor/`scanned_to` design already admits a filter later without a format change.
2. **#419: how a displayed lower bound avoids the pair overcount.** Options: (a) schema v5: allow `count = 0` on the pre-outage row (coverage only) and migrate; (b) read-time pairing rule (`sum - 1`) as designed above, no schema change; (c) accept the overcount and label it. Recommendation: (b) now, and fold (a) into one later v5 together with #430 if the owner wants exact rows. Why: the overcount is one event on an already-uncertain row, a v5 migration is a durable format change for a display total, and (b) can only under-report, which a lower bound allows.
3. **#430: prefix versus process evicted markers.** Options: (a) leave the writer as is and have the reader treat every `evicted` row as "some events in this span removed", never as an empty span; (b) a v5 discriminator (new `gaps` column or cause) so the ledger stops merging them and the reader can say "everything before X is gone" for a prefix; (c) fix only the merge in `mergeable()` by also comparing `end_ms` ordering. Recommendation: (a) in this PR, and (b) as its own small PR before PR 11 if the owner wants the stronger prefix statement. Why: the reader's honesty does not need the discriminator, only the ts-0 merge (which can delete closed sessions) needs it and is a write-side bug outside "the reader"; it needs the owner because it is a format change.
4. **Standing labels for sessions before the current one.** Options: (a) `unknown` for earlier sessions (labels are in-memory); (b) persist per-session label flags (schema v5, a column on `sessions`); (c) assume the current session's labels apply everywhere. Recommendation: (a). Why: (c) would state something we do not know, (b) adds a durable format for a flag the design deliberately keeps in memory, and "unknown" is honest and cheap. Revisit if the GUI needs "stock daemon on 12 Nov".
5. **When a response slot is released.** Options: (a) when the page is handed to the sender; (b) when it has been written to the socket or after `SEND_DEADLINE = 5 s`; (c) never until the client reads. Recommendation: (b). Why: (a) lets a slow client queue many 256 KiB pages behind the sender, (c) lets one token holder starve everyone, (b) bounds both memory and starvation. The 5 s value is a guess to confirm in PR 11 with the real socket.
6. **Reader pool and limits: fixed numbers.** Options: keep D8's 2 readers and 2 slots, 100 ms statement budget, 512-entry scan window, 20,000-entry scan cap, 100 gap rows per page; or make them settings. Recommendation: constants in `reader.rs`, not settings. Why: they are safety bounds, not preferences; settings would make them part of the consent/retention surface and of PR 10's validation.
7. **Reader refusal while a control operation runs.** Options: (a) `busy` (same as full); (b) a distinct `unavailable: control operation in progress`. Recommendation: (b). Why: the GUI should not retry-spin on `busy` while a clear is running, and it keeps `busy` meaning "try again soon" for PR 11.
8. **Open per query versus a pooled read connection.** Options: (a) open and close per query; (b) one pooled connection per slot. Recommendation: (a). Why: at most 2 queries at once and each path is a short sequence; a pooled fd would survive a clear's unlink and make the quiesce proof harder.
